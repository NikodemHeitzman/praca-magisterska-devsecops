  - kolejność `db` i `s3` → `migrate` → `seed` → `app`.
- `app/scripts/ci-env.sh`: tworzy `app/.env` z `.env.example` z losowymi wartościami (`openssl rand -hex`), maskuje je w logu GitHub Actions i nie nadpisuje istniejącego `.env`.

- Sprawdzenie lokalne (Docker 29.9.2, Compose 5.6.1):
  - `docker compose down -v`, potem `docker compose up -d --build`: 15,3 s do uruchomienia `app` (warstwy obrazu w pamięci podręcznej), `migrate` i `seed` kończą się kodem 0, `app` w stanie `healthy`,
  - `/health` zwraca `{"status":"ok","database":"ok"}`, logowanie `alice` (200), lista zgłoszeń z danych startowych, pobranie załącznika startowego (200), wgranie (201) i pobranie (200) nowego załącznika,
  - drugie `docker compose up -d` bez zmian w danych (`seed` idempotentny, `app` nie restartuje się); po restarcie `s3` i `up` pobranie załącznika startowego zwraca 200,
  - `docker compose up -d --wait` kończy się kodem 0 przy zdrowej `app`,
  - symulacja CI na kopii z `git archive HEAD` (bez `.env`): `up` kończy się błędem `required variable POSTGRES_PASSWORD is missing a value`; po `sh scripts/ci-env.sh` stos startuje, logowanie `alice`, `bob` i `admin` zwraca 200; drugie wywołanie skryptu odmawia nadpisania `.env`.

### Decyzje
- [ADR-0023](../adr/0023-uruchamianie-stosu-docker-compose.md), decyzje autora:
  - Docker Compose, powody: jedno źródło lokalnie i w CI, deklaratywność i prostota, skala projektu; odrzucone: `services:` w GitHub Actions, Kubernetes (kind, minikube);
  - jednorazowe usługi `migrate` i `seed`, powód: jedno polecenie do gotowej aplikacji; odrzucone: tylko migracje w compose, osobne polecenia;
  - `.env` w CI tworzony przez workflow, powód: żadnych sekretów w repozytorium; odrzucone: `compose.ci.yaml` z jawnymi wartościami, opcjonalny `.env` z wartościami domyślnymi;
  - wartości losowe przy każdym przebiegu (odrzucone: GitHub Secrets); powód: TODO: zweryfikować z autorem.
- `compose.yaml` zostaje w `app/` (decyzja autora), choć rezultat na tablicy to `compose.yaml`.

### Problemy
- Pierwsza próba symulacji CI: `git archive | tar -x -C` ze ścieżką Windows w Git Bash niczego nie rozpakowała. Obejście: ścieżka w postaci `/c/Users/...`. Prawdziwy `app/.env` nie został naruszony.
- [otwarte] Czy compose z usługą `seed` posłuży też do wdrożenia na EC2 i jak w AWS mają powstawać konta startowe: E05-03, E05-07.
